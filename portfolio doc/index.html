01 — Motive

Why the platform exists

Luxury DTC demos often stop at a landing page. Carts reset, filters return zero rows, and images 404. VALENCE ships the full loop — catalog, PDP, checkout, account, admin seed — so a buyer can click through a credible atelier in one session.

54-SKU floor

Obsidian Shell Parka ($890), Voltage Knit Crew, Monolith Overcoat ($1,180) — p1–p54 in catalog.ts + catalog-floor.ts, 9 categories, XS–XL variants.

Commerce state

Cart and wishlist in CommerceProvider with local persistence; orders and reviews persist to TiDB when configured.

One ops stack

Admin login, product visibility, order table, and POST /api/admin/seed — fed by sql/valance.sql on TiDB Cloud.

02 — Why it was built

Market friction vs product response

Friction

  • Missing max price param caps the shop at $0–$10 and looks “broken”
  • Dead CDN photos collapse every card into the same error fallback
  • Demo stores with no database lose orders on refresh

Response

  • ShopExperience parses min/max only when present; default band $0–$2000
  • npm run verify:images audits catalog URLs before ship
  • DB_* + DB_SSL to TiDB; /api/health reports connected product count

05 — Fusion intelligence

06 — Full picture

What VALENCE is — and why we built it

What it does
A production-grade luxury commerce demo: shop, PDP, cart, checkout, account, wishlist, admin, and optional AI stylist. Data layer supports in-memory fallback or TiDB/MySQL via sql/valance.sql.
Why we made it
To prove autonomous commerce UX — matte brand, real filters, real images, database-backed orders — in one Next.js codebase deployable in minutes.
Who it is for
Portfolio showcases, agency pitches, and engineers learning App Router + TiDB + Vercel production patterns.
What shipped
Next.js 14.2 · React 18 · Tailwind · Framer Motion · mysql2/pg · Stripe · sql/valance.sql · TiDB Cloud database valance · Vercel production · GitHub pirthvi-r12/valence-commerce · Demo users admin@valence.studio / avery@valence.studio.
